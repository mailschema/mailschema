# Standards checks for the 0.3 text

Checked against primary sources on 2 October 2026. RFCXML references pin the normative dependencies; this note records boundaries that are easy to misstate.

| Source                                                                                                                                                                                                                      | Use and boundary                                                                                                                                                                                                                                                                                                      |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [Structured Email -06](https://datatracker.ietf.org/doc/html/draft-ietf-sml-structured-email-06)                                                                                                                            | Sections 4.1-4.3 define designation and placement. Section 5.1 requires stripping non-representative data on manual forwarding; MAP deliberately imposes its own stronger copy rule. Section 5.3 requires SUPERSEDES for updates. Section 5.2 discusses future structured replies, not a reserved MAP execution slot. |
| [DKIM, RFC 6376](https://www.rfc-editor.org/rfc/rfc6376.html), [RFC 8301](https://www.rfc-editor.org/rfc/rfc8301.html), [RFC 8463](https://www.rfc-editor.org/rfc/rfc8463.html)                                             | Signature/body/header rules and current algorithm requirements. MAP adds required coverage and excludes every l= signature; it does not claim these are general DKIM delivery rules.                                                                                                                                  |
| [DMARC, RFC 9989](https://www.rfc-editor.org/rfc/rfc9989.html)                                                                                                                                                              | Strict/relaxed alignment and Organizational Domain discovery. No last-two-label shortcut or assumption that a tenant equals a domain.                                                                                                                                                                                 |
| [Authentication-Results, RFC 8601](https://www.rfc-editor.org/rfc/rfc8601.html)                                                                                                                                             | Configured receiving trust boundaries. A passing result is insufficient by itself to prove MAP-specific signature coverage or unchanged machine content.                                                                                                                                                              |
| [HTTP, RFC 9110](https://www.rfc-editor.org/rfc/rfc9110.html)                                                                                                                                                               | Safe methods, selected representations, strong If-Match, 412, 202, and ordinary HTTP semantics. The service can instead use its existing atomic expected-version argument.                                                                                                                                            |
| [Problem Details, RFC 9457](https://www.rfc-editor.org/rfc/rfc9457.html)                                                                                                                                                    | Optional reuse; no mandatory MAP problem envelope or six new registered problem types.                                                                                                                                                                                                                                |
| [RFC 8707](https://www.rfc-editor.org/rfc/rfc8707.html), [RFC 9700](https://www.rfc-editor.org/rfc/rfc9700.html)                                                                                                            | Resource-specific token audience protections; the email never selects a credential destination.                                                                                                                                                                                                                       |
| [One-click unsubscribe, RFC 8058](https://www.rfc-editor.org/rfc/rfc8058.html)                                                                                                                                              | Fixed request and scanner lessons. The MAP capability binding is a separate experiment, not unsubscribe interoperability.                                                                                                                                                                                             |
| [NIST SP 800-63A-4, section 3.8](https://pages.nist.gov/800-63-4/sp800-63a/ial-general/#ConfirmCodes)                                                                                                                       | Email confirmation codes expire within 24 hours and are invalidated on use in that publication's scope. MAP adopts those bounds; it does not equate address validation with authentication.                                                                                                                           |
| [RFC 7493](https://www.rfc-editor.org/rfc/rfc7493.html), [RFC 8785](https://www.rfc-editor.org/rfc/rfc8785.html)                                                                                                            | I-JSON and deterministic canonical contract hashing. MAP adds explicit size/depth/numeric limits.                                                                                                                                                                                                                     |
| [JSON Schema 2020-12](https://json-schema.org/draft/2020-12/json-schema-validation), [JSON-LD 1.1](https://www.w3.org/TR/json-ld11/)                                                                                        | Draft companion schemas and fixed offline context. Schema validation never proves authority or temporal consistency.                                                                                                                                                                                                  |
| [Unicode UTS #39](https://unicode.org/reports/tr39/)                                                                                                                                                                        | Display spoofing defenses; no blanket normalization of opaque service tokens or email local parts.                                                                                                                                                                                                                    |
| [IETF 127 important dates](https://datatracker.ietf.org/meeting/127/important-dates/), [SML charter](https://datatracker.ietf.org/group/sml/about/), [DISPATCH charter](https://datatracker.ietf.org/group/dispatch/about/) | Individual draft preparation and venue discussion. Neither the date nor use of the SML container implies working-group adoption.                                                                                                                                                                                      |
